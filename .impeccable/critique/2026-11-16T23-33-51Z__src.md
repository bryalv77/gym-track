### Design Specificity Verdict

**LLM assessment**: `gym-track` is cleanly engineered with a disciplined iOS Human Interface Guidelines (HIG) aesthetic, but its composition, visual language, and interaction model feel like the **iOS Settings app wearing a barbell icon** (`ListGroup.tsx:10` literally documents itself as `/** iOS inset-grouped list container (like the Settings app). */`) rather than an athletic training & coaching tool used on a gym floor.
- **Settings-app visual DNA**: `src/theme/index.ts:39-103` uses stock Apple `systemBlue` (`#007AFF` / `#0A84FF`) and `systemGray6` (`#F2F2F7` / `#1C1C1E`) with standard SF text styles (`lines 123-135`), zero athletic contrast, and no tabular numeral discipline (`fontVariant: ['tabular-nums']` is missing across all counters, steppers, and charts in `Text.tsx`, `Stepper.tsx:73`, and `BarChart.tsx:46`).
- **Binary checklist vs. set-by-set training**: `TodayScreen.tsx:287-335` (`AssignmentRow`) collapses an entire multi-set strength prescription (`3 sets · 10 reps · 40 kg`), completion timestamp, calories, and coach notes into a single 13pt `footnote` gray string (`ListGroup.tsx:86-97`) with one binary 24×24px `Checkbox` (`Checkbox.tsx:15-26`). There is no set-by-set logging, actual weight/rep recording, or rest timer.

**Deterministic scan**: `impeccable detect --json src` returned `[]` (0 findings, exit code 0). Because `gym-track` is built with React Native / Expo primitives (`<View>`, `<Text>`, `StyleSheet.create` in `.tsx` files) rather than raw web HTML/CSS stylesheets, the HTML/CSS rule engine reports a clean scan and cannot catch the React Native contrast failure (`tertiaryLabel` at 30% opacity = ~1.9:1 contrast in `src/theme/index.ts:66`), fixed-height Dynamic Type clipping, or missing React Native `accessibilityRole`/`accessibilityState` props identified in Assessment A.

### Overall Impression

The codebase has a remarkably clean, unified token and component architecture, but the UX treats physical training like a static to-do list and forces coaches through high-friction CRUD modals (`Stepper`-only number entry and unbounded `Chip` clouds). The single biggest opportunity is transforming `TodayScreen` from a passive settings checklist into an active, legible gym-floor workout companion while giving coaches scalable programming tools.

### What's Working

1. **Zero-Flash Semantic Theme Architecture (`src/theme/index.ts:48-103`, `src/theme/ThemeProvider.tsx:26-66`)**: Every primitive in `src/ui/` dynamically consumes semantic tokens (`colors.surface`, `colors.label`, `colors.blueTint`) via `useTheme()`, allowing instant System/Light/Dark switching in `ProfileScreen.tsx:227-231` without losing navigation state.
2. **Routine Snapshot Isolation & Preview Clarity (`src/components/AssignRoutineModal.tsx:111-121`, `src/screens/member/TodayScreen.tsx:87-105`, `src/components/AssignExerciseModal.tsx:155-167`)**: Assigning a routine stamps `routineId` and `routineName` onto individual assignments so members see exercises grouped cleanly by routine, while coaches can either edit one exercise's prescription or unassign the entire routine in one tap.
3. **Transparent Calorie & Streak Contextualization (`src/screens/member/TodayScreen.tsx:66-71, 180-189`, `src/components/ExerciseDetailSheet.tsx:83-87`)**: Calorie estimates dynamically incorporate the member's latest logged weight from `measurementsSlice` and explicitly state their basis (`"≈ 45 kcal (based on 75 kg body weight)"`) instead of showing opaque numbers.

### Priority Issues

- **[P0] What**: Workout Execution Is a Binary Grocery Checklist Buried Under a Giant Selfie Card (`src/screens/member/TodayScreen.tsx:192-238, 287-335`, `src/ui/ListGroup.tsx:52-106`, `src/ui/Checkbox.tsx:10-27`)
  - **Why it matters**: A member mid-workout with sweaty hands needs instant legibility of **Sets × Reps × Weight** at arm's length and per-set tracking. Placing a 320px tall 3:4 `"DAILY SELFIE"` card above the workout forces scrolling before the first lift, and compressing `3 sets · 10 reps · 40 kg` + notes into a 13pt 60%-opacity gray `footnote` subtitle makes prescriptions unreadable from the gym floor.
  - **Fix**: Demote the Daily Selfie card on `TodayScreen.tsx` to a compact single-row bar or move it below the workout list; replace the generic `ListRow` in `AssignmentRow` with a dedicated `WorkoutExerciseCard` featuring large tabular-numeral pills (`3 SETS`, `10 REPS`, `40 KG` in 17–20pt semibold), distinct coach note callouts, a 48×48px completion target with haptic feedback, and per-set checkoffs.
  - **Suggested command**: `/impeccable bolder`

- **[P1] What**: `- / +` Stepper-Only Weight Programming & Overloaded Multi-Exercise Routine Modal (`src/ui/Stepper.tsx:10-85`, `src/components/RoutineFormModal.tsx:164-240`, `src/components/AssignExerciseModal.tsx:249-261`, `src/ui/SheetModal.tsx:39`)
  - **Why it matters**: `Stepper` only supports single `- / +` taps (`2.5 kg` step for weight in `src/utils/exercisePresets.ts:9`), so programming a 140 kg deadlift from the 40 kg default requires **40 consecutive taps** on a 38×32px target. Meanwhile, `RoutineFormModal` expands every exercise's steppers and notes simultaneously inside a bottom sheet where a single accidental backdrop tap (`SheetModal.tsx:39`) destroys all unsaved work.
  - **Fix**: Make the numeric readout in `Stepper.tsx:73-75` a tappable `TextInput` (`keyboardType="decimal-pad"`) for direct keyboard entry, add press-and-hold repeat, increase button height to 44px, collapse routine items in `RoutineFormModal.tsx` into expandable accordion rows, and guard `SheetModal` backdrop dismissal when dirty.
  - **Suggested command**: `/impeccable distill`

- **[P1] What**: Dead-End Coach Member Directory & Unbounded Filter Chip Clouds (`src/screens/coach/MembersScreen.tsx:101-118`, `src/screens/coach/PlanScreen.tsx:114-129`, `src/components/AssignExerciseModal.tsx:169-181, 229-236`)
  - **Why it matters**: Tapping a member row in `MembersScreen.tsx` does nothing (`onPress` is omitted), forcing coaches to memorize a member's name and manually filter `PlanScreen`. Additionally, rendering all members and all library exercises as wrapping `Chip` clouds (`flexWrap: 'wrap'`) will push content off-screen as soon as a gym exceeds 10–15 members or exercises.
  - **Fix**: Make `MemberRow` in `MembersScreen.tsx:107` navigate to that member's plan/progress view; convert the member filter bar in `PlanScreen.tsx:195` to a horizontal scroll strip (`ScrollView horizontal`); and group/filter exercise pickers in modals by category (`Suggested`, `Strength`, `Cardio`) + search.
  - **Suggested command**: `/impeccable shape`

- **[P1] What**: Silent Failures on Mutations, Invisible Initial Data Hydration, and Unlocalized Modal Metric Labels (`src/components/DataSync.tsx:91`, `src/screens/member/TodayScreen.tsx:117-119`, `src/components/AssignExerciseModal.tsx:148-150, 251`, `src/components/RoutineFormModal.tsx:196`)
  - **Why it matters**: `DataSync.tsx` renders `null` with no loading state in Redux, flashing false empty states (`"No exercises yet"`) on startup. Failed network mutations in `TodayScreen`, `ProgressScreen`, `AssignExerciseModal`, and `ExerciseFormModal` only `console.warn` with zero user alert or optimistic rollback. Furthermore, `AssignExerciseModal.tsx:251` and `RoutineFormModal.tsx:196` render raw English `field.label` instead of calling `metricLabel(field)` (`src/utils/exercisePresets.ts:32`), breaking localization in ES/FR/DE/PT.
  - **Fix**: Add a `hydrated` state to Redux in `DataSync.tsx` so screens show skeletons/spinners until initial fetch completes; surface mutation errors via toast/alert with optimistic rollback; and wrap `field.label` in `metricLabel(field)` across all modals.
  - **Suggested command**: `/impeccable harden`

- **[P2] What**: Accessibility Gaps, Low-Contrast Tertiary Text (~1.9:1), and Destructive Form Inputs (`src/theme/index.ts:66`, `src/ui/TabBar.tsx:49`, `src/ui/Chip.tsx:16-23`, `src/components/ExerciseFormModal.tsx:161-165`, `src/components/MeasurementFormModal.tsx:108-114`)
  - **Why it matters**: Custom primitives (`TabBar`, `SegmentedControl`, `Chip`, `Button`, `ListRow`, `SheetModal` close button) lack `accessibilityRole`, `accessibilityState`, and `accessibilityLabel` props; `tertiaryLabel` (`rgba(60,60,67,0.30)`) fails WCAG AA at ~1.9:1 contrast; switching exercise type in `ExerciseFormModal.tsx:161-165` wipes custom fields without warning; and `MeasurementFormModal.tsx:108-114` asks users to type raw `YYYY-MM-DD` strings.
  - **Fix**: Add proper accessibility roles/states/labels to all `src/ui/` primitives, raise `tertiaryLabel` opacity to at least `0.55`, guard custom fields before resetting on type switch in `ExerciseFormModal`, and reuse `DatePager`/`CalendarMonth` in `MeasurementFormModal`.
  - **Suggested command**: `/impeccable audit`

### Persona Red Flags

**Casey (Distracted Mobile User — One-Handed on the Gym Floor)**:
- `Checkbox.tsx:26` is a 24×24px visual box inside a full-row `Pressable` (`TodayScreen.tsx:332-333`) where a slightly off-center thumb tap opens `ExerciseDetailSheet` instead of checking off the exercise.
- `TodayScreen.tsx:201-214` places 18px Selfie edit and delete icon buttons only `14px` apart (`line 346`), risking accidental deletion with shaky post-workout hands.
- `DatePager.tsx:86-91` previous/next day chevrons are `32×32px` with no `hitSlop`.

**Alex (Impatient Power User — Coach Programming Routines)**:
- Programming weights via `Stepper.tsx:44-68` without keyboard entry or long-press repeat takes dozens of taps per exercise.
- Primary creation buttons (`"Assign Exercise"`, `"New Routine"`, `"New Exercise"`, `"New Gym"`) are placed at the *bottom* of the scroll view below the list in `PlanScreen.tsx:167-184`, `RoutinesScreen.tsx:86-92`, `ExercisesLibraryScreen.tsx:106-115`, and `GymsScreen.tsx:84-93`, scrolling off-screen as the library grows.
- No way to copy a day's plan to another date or assign a routine across multiple days of the week.

**Jordan (Confused First-Timer — New Gym Member)**:
- `SignUpScreen.tsx:110-121` displays `"Coach code (optional)"` prominently to every new user, confusing regular members into thinking they need a code from their trainer (when `coachCode` actually grants `coach` privileges).
- `MeasurementFormModal.tsx:108-114` asks for `Date (YYYY-MM-DD)` in a plain text box, and `ExerciseFormModal.tsx:222-227` asks for raw `"Intensity MET"`.

**Sam (Accessibility-Dependent User)**:
- `TabBar.tsx:49`, `SegmentedControl.tsx:48`, and `Chip.tsx:16-23` omit `accessibilityRole` and `accessibilityState={{ selected }}`, making VoiceOver/TalkBack unable to announce which tab or chip is active.
- `SheetModal.tsx:55-57` close (`X`) button has no `accessibilityLabel`.
- Fixed pixel heights on text containers (`Chip.tsx:37` `height: 30`, `Badge.tsx:26` `height: 20`, `SegmentedControl.tsx:63` `height: 32`, `NavBar.tsx:64` `height: 44`) clip text under iOS Larger Accessibility Dynamic Type sizes.
